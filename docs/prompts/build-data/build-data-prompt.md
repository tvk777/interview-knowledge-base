Implement `scripts/build-data.ts`.

The purpose of this script is to convert one source dataset into the generated dataset.

## Goal

Read one source JSON file from:

data/original/<technology>.json

Convert every AnswerBlocks array into Markdown using the existing

answerBlocksToMarkdown()

function.

Write the generated dataset to:

data/generated/<technology>.json

The script must process exactly one technology per run.

Example:

npm run build-data react

should read

data/original/react.json

and produce

data/generated/react.json

Do not implement a "build all" mode.

---

## Before coding

Inspect the existing source dataset structure.

Reuse all data that already exists.

Do not change the existing Markdown renderer.

---

## Requirements

- Reuse the existing `answerBlocksToMarkdown()` implementation.
- Do not duplicate Markdown conversion logic.
- Keep the implementation simple (KISS).
- Use plain functions.
- No classes.
- No factories.
- No abstractions for future features.

This script must perform only deterministic data transformation.

Do not implement any AI functionality.

---

## Target schema

The generated dataset must already follow the application's final schema.

Populate every field that can be derived directly from the source dataset.

Fields that require AI (translations, metadata, etc.) should be initialized with empty values.

The generated objects should have this structure:

```json
{
  "id": "...",
  "tags": [],
  "level": "",
  "category": "",
  "question": {
    "en": "...",
    "uk": ""
  },
  "answer": {
    "en": "<generated markdown>",
    "uk": ""
  }
}
```

Requirements:

- `question.en` comes from the source dataset.
- `question.uk` is an empty string.
- `answer.en` is generated by `answerBlocksToMarkdown()`.
- `answer.uk` is an empty string.
- `tags` is an empty array.
- `level` is an empty string.
- `category` is an empty string.

Do not include `answerBlocks` in the generated dataset.

The goal is that a future `enrich-data.ts` script will populate the empty fields without changing the schema.

---

## CLI

The script accepts one required argument:

- react
- javascript
- nextjs
- typescript

If the argument is missing:

- print usage
- exit with a non-zero status code.

If the technology is unknown:

- print a clear error message.
- exit with a non-zero status code.

---

## File system

Create `data/generated` if it does not exist.

Overwrite the generated file if it already exists.

Write formatted JSON using 2-space indentation.

Use UTF-8 encoding.

---

## Error handling

Fail fast.

If:

- the input file does not exist;
- the JSON is invalid;
- writing the output fails;

print a readable error message and exit with a non-zero status code.

Do not silently ignore errors.

---

## Validation

After implementation:

- run the script for every existing technology;
- verify that every generated file is valid JSON;
- verify that `answerBlocks` no longer exist;
- verify that every `answer.en` contains the generated Markdown;
- verify that all UTF-8 characters are preserved.

Report the validation results.
